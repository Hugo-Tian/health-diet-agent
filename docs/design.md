# 实施设计

原始需求见根目录《健康饮食Agent_整体设计与CodexPrompt.md》。文档内角色提示词作为需求参考，不作为运行期 agent 指令。

## 范围与阶段

A：FastAPI / SQLAlchemy / Alembic，账号、档案、演示食物库、确定性计算。
B：Vue 3 / TypeScript / Pinia / Router，草案确认、日志、汇总、替换及版本冲突。
C：有界工具工作流、可配置兼容模型接口、历史、趋势、导出删除。
D：后端测试、前端构建、浏览器流程与响应式检查、启动和部署文档。

开发 SQLite，生产 PostgreSQL；业务数据只存后端。认证采用随机会话令牌的 HttpOnly Cookie，写请求须带同会话 CSRF token。会话只在数据库保存哈希。密码 scrypt。事务通过用户 revision 的原子比较更新串行化用户写操作。所有用户资源查询限制 owner。

用户在开发过程中明确追加“用 langchain 架构”：Agent 层已改为 LangChain @tool / RunnableLambda / ChatOpenAI.bind_tools，服务端有界编排。无需复杂多 Agent 框架。模型可提供候选食物 ID 和份量，后端重算并验证，不接受模型营养数字。

每个计划/日志项保存营养与来源快照。缺失营养保留 null，汇总显示已知量和未知项数。已吃过的餐次禁止替换；日志撤回或编辑会增加 revision，使旧草案失效。调整重复确认返回先前结果。每用户/日期 active plan 由 DailyState 唯一行指定，历史版本保留。

档案可不完整；生成按食物组结构，不推断性别、不计算未经核验的个性化热量目标。特殊人群保留记录和一般结构示例，禁止自动限制性目标。用户预算仅显示为预算，不伪造价格。当前食物库包含 79 个 USDA SR Legacy 参考条目，保留原始营养证据、单位和来源；历史 demo 快照独立标注。参考值不代表本地具体菜品实测值。

## 界面设计

颜色：纸白 #f5f8fc、海蓝 #2557a7、墨蓝 #18304f、浅蓝 #e6eefb、叶绿 #28745a、提示棕 #815b20。
字体：中文正文 Microsoft YaHei / PingFang SC；标题同字体加粗；数字使用等宽数字排版。
桌面左栏 + 内容区：顶部日期与状态，下方三餐餐盘和实际摄入账本；移动端单列 + 底部五项导航。左对齐、空间层级取代重复阴影卡片。餐盘是唯一醒目视觉元素，用 CSS 食物色块体现结构，装饰不用于伪造营养比例。

## 验收策略

核心 API 测试覆盖完整闭环、租户隔离、过敏和素食约束、重复确认、旧版本冲突、已吃餐锁定、时区、缺失值、快照不变、删除与反馈失效。前端运行 TypeScript 检查、生产构建和浏览器流程。无真实密钥时只验证模拟协议和故障回退，不声称真实 provider 已连通。
